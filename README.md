# 库迪咖啡选址系统（杭州）

一个基于 **WebGIS + 空间数据库** 的连锁咖啡门店智能选址分析系统。以杭州西湖区、滨江区为研究区域，通过叠加分析 + 缓冲区打分 + 蜂窝网格栅格化，为库迪咖啡科学地推荐最优开店位置。

---

## 一、项目背景

连锁品牌开店选址通常依赖"经验 + 主观判断"，存在两个痛点：

1. **缺乏量化依据**：难以回答"这个位置到底比另一个位置好多少？"
2. **忽视竞品格局**：只看客流，不考虑竞争对手的覆盖范围，容易扎堆或陷入盲区。

本系统用空间分析的手段，把"在哪里开店"这个主观问题，转变成可以计算、可以可视化、可以复用的数据问题。

---

## 二、技术栈

| 层级 | 技术 | 作用 |
|------|------|------|
| 前端框架 | Vue 3 + TypeScript | 组件化界面开发 |
| 构建工具 | Vite | 开发服务器 + 接口代理 |
| 地图引擎 | OpenLayers | 地图渲染、图层管理、绘制交互 |
| 空间计算（客户端） | turf.js | 蜂窝网格生成、客户端几何运算 |
| 后端框架 | Express（Node.js） | 空间分析 REST API |
| 空间数据库 | PostgreSQL + PostGIS | POI 存储 + 空间查询（KNN、缓冲区、包含判断） |
| 地图服务 | GeoServer | 通过 WFS 协议发布 POI 空间数据 |

> 数据规模：POI 点位 **1200+**（写字楼/产业园 400、高校 200、库迪门店 120、竞品门店 480），覆盖西湖区与滨江区。

---

## 三、核心功能与整体思路

系统围绕"**服务劣势诊断 → 缓冲区叠加打分**"两步分析法展开：

### 1. 服务劣势诊断（找"痛点"）

对商圈内的每一个消费群体点（写字楼 / 高校），计算它到**最近库迪门店**和**最近竞品门店**的距离，若满足以下任一条件，即判定为"高潜力抢夺目标"：

- **竞争劣势**：竞品比我们近太多（距离差超过阈值）
- **绝对盲区**：我们的门店离该消费点实在太远（超过盲区阈值）

> 技术实现：PostGIS 的 `KNN 最近邻查询`（`<->` 操作符 + GIST 空间索引）替代全表距离计算，时间复杂度从 O(N) 降到 O(logN)。

### 2. 缓冲区叠加打分（算"最优解"）

- 对高潜力消费点生成**双层缓冲区**（内圈 = 绝对便利区，环带 = 较便利区）
- 将整个商圈切分为**六边形蜂窝网格**（相比正方形网格，各向同性更好、边界效应更小）
- 对每个六边形中心点，按"到各消费点的距离分档"累加得分
- 按**百分位分档着色**，得分最高的深红色区域即推荐开店位置

### 3. 可视化与交互

- 行政区 / 手绘自定义商圈（ROI）两种分析模式
- POI 按类型分色显示，ROI 内高亮、ROI 外灰显
- 悬浮查看蜂窝网格得分，动态百分位图例

## 四、技术架构

```
┌─────────────────────────────────────────────┐
│              Vue 前端 (localhost:5173)        │
│   Sidebar(控制面板)  +  MapContainer(地图)     │
└──────────┬────────────────────┬──────────────┘
           │ WFS 协议(加载数据)  │ REST API(空间分析)
           ▼                    ▼
   ┌──────────────┐    ┌──────────────────┐
   │  GeoServer   │    │   Express 后端    │
   │  (localhost:8080) │   (localhost:3001) │
   │  发布 POI 数据    │   执行诊断/打分计算 │
   └──────┬───────┘    └────────┬─────────┘
          │                     │
          └──────────┬──────────┘
                     ▼
        ┌─────────────────────────────┐
        │  PostgreSQL + PostGIS        │
        │  (localhost:5432)            │
        │  poi 表 (1200+ 条空间数据)    │
        └─────────────────────────────┘
```

**设计思路**：GeoServer 负责"把数据搬出来"（数据发布），Express 负责"把数据算好"（空间分析），两者平级、各司其职，共同连接同一个空间数据库。前端只做展示与交互，不再在浏览器端执行重型空间计算。

## 五、应用价值与利他性

本系统的方法与架构不只服务于库迪咖啡，它是一套**可迁移、可复用的空间选址方法论**：

**对连锁品牌方（咖啡 / 茶饮 / 便利店 / 药店等）**
- 把开店决策从"拍脑袋"变成"看数据"，量化每个候选点的竞争态势与服务盲区，降低试错成本。

**对中小创业者与个体商户**
- 原本只有头部品牌才用得起昂贵的商业 GIS 分析，本系统用**开源技术栈**（PostGIS + GeoServer + OpenLayers）实现了同等能力的低成本方案，让普通人也能科学选址。

**对商业地产与园区运营方**
- 直观了解片区内的商业服务覆盖缺口，辅助招商定位与业态规划。

**对 WebGIS 学习者与开发者**
- 完整展示了"前端 → 后端 → 地图服务 → 空间数据库"全链路架构，以及 turf.js 计算迁移到 PostGIS 的完整实践，可作为空间分析系统开发的参考范例。

## 六、快速开始

### 环境要求

- Node.js ≥ 22
- PostgreSQL 15+（已启用 PostGIS 扩展）
- GeoServer 2.x/3.x（已配置 `cotti` 工作区与 PostGIS 数据源）

### 启动步骤

```bash
# 1. 启动 PostgreSQL（系统服务，通常开机自启）

# 2. 启动 GeoServer（独立的 Java 服务）
#    Windows: 双击 GeoServer 安装目录下 bin/startup.bat

# 3. 安装依赖（首次）
npm install

# 4. 启动 Express 后端（localhost:3001）
npm run dev:server

# 5. 启动前端（localhost:5173）
npm run dev
```

> 数据库连接信息通过项目根目录的 `.env` 文件配置（含 `DB_PASSWORD`），不硬编码在源码中。

### 数据说明

- POI 数据存储于 PostgreSQL `poi` 表，通过 GeoServer WFS 实时发布，前端按类型（写字楼/高校/库迪/竞品）通过 CQL 过滤按需加载。
- 行政区边界数据来自阿里云 DataV 开放 API。
